01
Clean Both Datasets Complete all cleanup before any comparison
📋 SharePoint Working File → Clean before touching Entra
👆 SharePoint — What to Clean
  • 1
    Trim and UPPERCASE all serial numbers — no spaces, no mixed case
  • 2
    Trim and lowercase all email addresses — consistency required for matching
  • 3
    Trim device names — normalize case, note any naming pattern inconsistencies
  • 4
    Flag blank serials — research each one before continuing
  • 5
    Flag placeholder serials: N/A UNKNOWN TBD 000000
  • 6
    Find duplicate serials — each must appear exactly once. Identify the active record.
  • 7
    Standardize status values: Assigned · In Stock · Repair · Retired · Loaner
⚠️ Why Each Step Matters

Serials in different case will not match. "abc123" ≠ "ABC123" in most join logic.

Email case mismatches cause false ownership mismatches — same person, different case, no match.

Duplicate serials cause one-to-many joins — your row count will inflate and look correct even when wrong.

Inconsistent status values like "assigned" vs "Assigned" create false filter failures in downstream review.

Retired devices in Entra are a cleanup signal — they should have been removed at offboarding.

02
Establish Match Logic Same priority order for every record — no exceptions
🔗 Reconciliation Workbook → Match logic applied before any joins
📌 Always follow the same priority order. Do not mix methods between records. Inconsistent matching produces unreliable results — and the output will look correct even when it isn't.
💻 Laptop & Workstation Priority
1 Serial Number Primary. Most reliable. Always try first.
2 Device Name Use if serial is missing or inconsistent.
3 User Email Last resort. Not unique — one user may have multiple devices.
📱 Mobile Device Priority
1 Serial / IMEI Primary. Use device serial or IMEI from MDM or SharePoint.
2 Device Name Secondary if serial is unavailable.
3 User Email Last resort only. Same caution applies.
💬Common Match Logic Questions — tap to expand
Email is not unique to a device. If a user has two laptops, both will appear to match — even if one is genuinely missing from a system. Serial number is the only field that is truly unique to one physical device.
Device names can change during imaging, reimaging, or reassignment. The physical hardware never changes its serial number. Hostname mismatches are common — that's why serial is authoritative and name is only a fallback.
Fall back to Device Name, then User Email — in that order. Flag the record as Needs Review and research the serial manually. Do not leave it unresolved — a missing serial means you cannot reliably match that device.
No. If the serial matches but the assigned user is different between systems, that is an ownership mismatch — not a gap. The device exists in both systems. The assignment record is just out of sync between them.

04
Validate Key Views Work through each exception category in order
🔍 Filter by each flag — review one exception category at a time
Missing from SharePoint ENTRA ONLY
▸Device is in Entra but has no corresponding SharePoint record
▸Indicates: unmanaged device or inventory record was never created
▸Action: Create the SharePoint record or confirm device status and disposition
Missing from Entra SHAREPOINT ONLY
▸Device is in SharePoint but has no Entra record
▸Indicates: retired device or stale inventory entry never cleaned up
▸Action: Verify device status and update or remove the SharePoint record
Ownership Mismatch MISMATCH
▸Device is in both systems but assigned to different users
▸Indicates: outdated assignment or inventory not updated after reassignment
▸Action: Confirm who currently has the device — update the lagging system
Stale Devices STALE
▸No recent sign-in detected in Entra — 90+ days
▸Indicates: cleanup candidate, unassigned device, or reclaim opportunity
▸Action: Review lastSignInDate — cross-check with SharePoint device status
Duplicate Assignments DUPLICATE
▸Same device appears assigned to more than one user in either system
▸Indicates: data entry error or reassignment not fully completed
▸Action: Confirm current user — remove the duplicate assignment from both systems

05
Manual Validation Do not skip — automation cannot catch its own errors
🔎 Spot-check minimum 20–30 records before trusting any output
🚨 Do not trust automation until this phase passes. A false mismatch sent to leadership damages trust in the process. Manual validation is not optional.
👆 What to Validate
  • →
    At least 20 laptop records and 20 mobile records
  • →
    At least 5 Valid Match rows — confirm both sides agree
  • →
    At least 5 Missing from Entra — confirm genuinely absent
  • →
    At least 5 Ownership Mismatch — confirm users are actually different
  • →
    At least 3 Stale Device rows — confirm lastSignInDate is accurate
  • →
    At least 2 Retired devices — confirm excluded from active counts correctly
⚠️ How to Spot a False Mismatch

Device shows Missing from Entra but you find it there manually → serial format is inconsistent. Go back to Phase 1 cleanup.

Ownership Mismatch shows the same person twice → name formatting differs between systems. Fix normalization.

Row count jumped after joining → a duplicate serial is causing one-to-many matches. Fix duplicates first.

Count looks right but spot-checks fail → data is wrong underneath. Stop and fix before continuing.
